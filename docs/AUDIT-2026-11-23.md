# Audit follow-up (23 November 2026)

What was done about each item in the developer handoff audit of `55d48ba`, and what's still open. Every fix has tests; the test names are listed so each one can be checked again.

## Fixed

| Item | What changed | Tests |
| --- | --- | --- |
| RT-BUG-001 FiveM runtime scripts | The FiveM build is now honestly **configuration only**. `server.cfg` no longer starts a `riptide-runtime` resource, and no manifest points at scripts that don't exist. World, economy, rules, access and schedule go to `riptide/blueprint-config.json` marked reference only, with a `riptide/README.txt` and an `FIVEM_CAPABILITIES` list of what's applied and what isn't. Unreleased catalog mods are left out of the build. "FiveM ready" wording is gone from the app, README, site and docs. | `fivem build: every file the server is told to load exists…`, `fivem build leaves out mods that aren't released` |
| RT-BUG-002 Simulated deploy said "live" | The button is **Run deployment simulation**, the log is a **Simulation log** marked "Not a real deploy", steps that don't happen are labelled "Simulated", and it ends with "Simulation complete. No server was started." Hosting costs are labelled a rough estimate, not a price. | manual check, Deploy screen |
| RT-BUG-003 Two windows overwriting each other | Each window keeps the last version it agreed with storage on, and merges instead of overwriting (`packages/tools/src/merge.ts`): field by field, record by record for lists with ids, as sets for lists of ids. Same-field conflicts take the edit being made in that window. It also re-checks storage right before saving, for saves whose event hasn't arrived yet. | merge unit tests incl. 200 interleaved edits; browser check `two windows editing the same tool at once keep both changes` |
| RT-BUG-004 Desktop resurrection and backup handling | A deleted file stays deleted (no restore from `.bak`, no copy back from browser storage); data that never reached disk is still copied once. Schema-invalid saves are recovered from the backup and the tool says so; a damaged file never replaces a good backup; storage-full during start-up holds writes to that file. | storage unit tests; browser checks `desktop: …`; packaged-app checks |
| RT-BUG-005 Backup import not transactional | Backups are version 2 with a checksum per part and include the interface choice. Restoring checks the whole file first (format, checksums, each tool's schema), shows what will change, and writes all or nothing, putting everything back if storage fills halfway. Version 1 backups still restore. | backup unit tests; browser check `backups: checked before restoring, all or nothing, and complete` |
| RT-BUG-006 ViceLab comparing incomparable runs | Recommendations only compare runs with the same hardware profile, scene, resolution and frame metric, report how many runs were left out, and say "Low confidence" (with reasons) when hardware or scene is missing or a preset was measured once. Runs now record a test scene. | `recommendations never compare runs from different hardware, resolutions or scenes`, `…low confidence` |
| RT-BUG-007 Presented vs displayed FPS | Presented and displayed frame times are kept apart; displayed is never filled in from presented. Rows from other processes or swap chains are left out (with a note), frames never displayed are counted, CapFrameX files with several runs import the first run only, and decimal commas are read. The UI labels which metric the numbers are. | `presented and displayed frames are kept apart` and five more parser tests |
| RT-BUG-008 Pop-ups blocked | Pop-out windows open within the click, then move to another display once the browser shares them. Restoring several windows opens them all before awaiting, and says which ones the browser blocked. | browser check `personal marker, categories and pop-out keep their state` |
| RT-BUG-009 Invalid clock times | Times must be 0:00–23:59 (or 1–12 with am/pm). `25:99`, `24:00`, `11:75` stay staff rules with a warning. Rules are labelled "parsed, not yet enforced" everywhere, and Discord output is split into continued fields, embeds and messages instead of cut off. | `clock times: real times only`, `rulebook: invalid times never become schedules`, `discord: long rulebooks are split, never cut off` |
| RT-BUG-010 Role loops | Duplicate role ids and inheritance loops (`a → b → a`, `a → a`) are rejected with the exact chain, and the FiveM build refuses them. | `roles: loops and duplicate ids are rejected…`, `fivem build refuses a Blueprint with a role loop` |
| RT-BUG-011 Docker and dependency order (partly) | The compose file and CLI say **example only** (the images aren't published). The load order uses one provider per requirement, so two providers no longer make a false loop. | `load order: one provider per need…`, `docker stack says it's an example` |
| RT-BUG-013 Countdown drift | The benchmark timer counts down from a fixed end time, so background tabs and sleep don't stretch it, and says it's only a timer. | browser check `start benchmark runs an honest timed session` (fast-forwards the clock) |
| RT-BUG-014 Outdated statuses (partly) | Roadmap: Studio is "FiveM config export", Workspaces mentions the desktop app, and the journal, route library and clip organizer are "buildable now" instead of waiting on GTA VI PC. The desktop app remembers the classic/Tools shell choice across restarts. | packaged-app check `the shell choice survived the restart` |
| Checklist: `app://` handling | Undecodable addresses, `../`, encoded slashes, backslashes, null bytes and symlinks leading outside the app folder are refused. | `desktop/test/appfiles.test.cjs`, packaged-app check `app:// only serves the app's own files` |
| RT-BUG-016 Release hardening (partly) | GitHub Actions are pinned to commit SHAs, Dependabot watches npm and Actions, and each release ships a `SHA256SUMS.txt`. | workflow YAML checks |

## Still open

- **RT-BUG-012:** no desktop release is published yet. Run Actions → Desktop app with `v0.1.0`; until then the download links return 404.
- **RT-BUG-016:** code signing (Windows) and notarisation (macOS), SBOM and artifact attestations, and Windows/macOS install-and-update tests in CI. Needs certificates.
- **RT-BUG-011:** publishing real, pinned server images with health checks; a FiveM runtime with an FXServer smoke test (RT-BUG-001's "real runtime" option).
- **RT-BUG-015:** storing map packs per pack instead of in one key, per-place verification status and patch version, and a takedown workflow.
- **RT-BUG-003 (long term):** moving storage to IndexedDB (browser) and SQLite (desktop) with per-record revisions. The merge fixes the lost updates today; the move is a larger, separate change.
- **ViceLab:** parsing very large captures in a Web Worker so a 50 MB file doesn't pause the page.
- **Product work** from sections 3–5 of the audit (Tonight planner, Map 2.0 routes, journal, garage ledger, crew rooms and the rest). The roadmap marks which of these are buildable now.
